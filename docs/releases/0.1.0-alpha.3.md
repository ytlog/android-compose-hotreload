# Android Compose Hot Reload 0.1.0-alpha.3

This is an Alpha release of the Android adapter. It continues to use the published
ART DCEVM `0.1.0-alpha.4`; it does not introduce a new ART engine release.

## 中文

### 改进

- 修复已覆盖的异步图片回调编辑触发整页重置、API 36 系统选择器在前台时后台重载超时的问题。
  唤醒原应用进程，不启动新 Activity 或替换原页面。
- 改进受限常量委托初始化和子组布局演进的状态保留；保留真实初始化／不兼容布局变化的重置边界。
- 连接、握手、半帧、写入和结果等待都有明确期限；正常空闲连接不超时。
  重载写入最多 10 秒，完整写出后另有 120 秒等待结果。
- 流式收发避免整帧重复缓冲；发送前检查大小，设备队列按消息数和字节数限制，包含正在写出的消息。
- 资源快照只保留初始元数据；资源未变化时只做流式摘要检查，不重复解压并保存全部资源。
- 请求 ID 贯穿 JB orchestration 与设备；补充阶段、原因、载荷大小和本机单调时钟耗时诊断。
  写入／等待结果期间断连仍明确表示“结果不确定”，不会自动重放或重启应用掩盖结果。
- 补充绘制／布局、导航扩展、内容切换动画、搜索竞争、表单、嵌套滚动、权限 launcher、
  方法引用、网络＋Room 分页及持续编辑等场景入口。

### 验证与边界

- 冻结前最新源码通过 83 项主机测试。API 36 定向回归共 19 项检查、10 次重载，
  覆盖 AndroidView、后台 Compose launcher，以及代码／资源更新；相关原页面状态保留，
  请求确认、设备执行和渲染日志按 ID 对应。
- 24 MiB 堆的独立 JVM 通过含 40 MiB STORED asset、128 MiB 解压后 asset 的初始／未变化资源检查。
  这不代表大尺寸变化包可以在同样堆大小内发送，也不是性能提升百分比测试。
- 之前通过且源码未受影响的协议、传输故障和其他页面检查按影响范围复用；上述设备结果来自
  同源码的本地候选构件，不冒充公开最终包的完整设备矩阵。发布流程另外验证完整发布物和独立版本号接入。
- **API 33 最新公共传输改动仍暂缓补验。** 历史通过项不代表本版双设备验收完成。
- 单次重载载荷（DEX＋资源 APK）上限 64 MiB；事件 1 MiB、控制消息 64 KiB，
  设备发送队列 4 MiB／256 条等待消息。超限在发送前拒绝，不保证应用整体不会内存耗尽。
- 不承诺任意旧对象初始化、捕获改型、协程状态机或 Compose 槽迁移；不自动重放结果不确定的事务。
  全天会话、真实 ADB 断连恢复、更多厂商／系统组合和 JNI 性能问题仍保留各自验证边界。

## English

### Changes

- Fix the covered asynchronous-image callback edits that reset remembered page state, and wake the
  original debug process for API 36 background reloads while a system picker is open.
- Preserve unaffected state across bounded delegate initialization and child-scope layout changes;
  genuine initializer and incompatible layout changes retain their reset semantics.
- Bound handshakes, partial frames, writes and acknowledgement waits while leaving true idle sessions
  unlimited. Reload writes have a 10-second deadline followed by a separate 120-second result window.
- Stream bounded protocol payloads, preflight outgoing sizes and account for in-flight bytes in the
  device queue. Keep installed resource metadata instead of APK contents and hash unchanged bundles
  without inflating their entries.
- Preserve upstream request IDs and add stage/reason/size/timing diagnostics. Uncertain transactions
  remain disabled for replay; a transport failure does not imply rollback or justify restarting the app.
- Expand targeted fixtures for drawing/layout, navigation extensions, content transitions, search,
  forms, scrolling, permissions, retained references, network-backed Room paging and sustained edits.

### Validation and scope

The latest frozen source passed 83 host tests and API 36 targeted acceptance comprising 19 checks
and 10 reloads across AndroidView, background Compose launchers and code/resource updates, preserving
relevant page state. Host, device-execution and rendered events correlate by request ID. A 24 MiB-heap
probe passes initial/unchanged checks for a 40 MiB stored asset and a 128 MiB expanded asset; this is
not a claim about changed-payload heap requirements or a speedup benchmark.

Unaffected earlier results are reused with their original source/artifact identities. Device results
come from source-equivalent local candidates, not a fresh full matrix of the final public artifacts.
The release workflow separately checks staged publications and isolated public version-based integration.
**API 33 validation of the newest shared transport changes remains deferred.** The release is not a
claim of universal device support, all-day stability, arbitrary state migration or JNI performance acceptance.

Reload payloads are limited to 64 MiB (DEX plus resources), events to 1 MiB and controls to 64 KiB.
The device queue allows 4 MiB including its in-flight frame and 256 waiting frames. Limits do not
prevent application-wide memory exhaustion. Unknown transactions are never automatically replayed.

## Version-based integration / 版本号接入

In the Android application module / 在 Android 应用模块中：

```kotlin
plugins {
    id("io.github.ytlog.compose.hot-reload.android") version "0.1.0-alpha.3"
}
```

Use `google()`, `mavenCentral()` and `gradlePluginPortal()` in `pluginManagement.repositories`,
and `google()` / `mavenCentral()` in dependency repositories. Both repository blocks also need the
pinned upstream repository:

```kotlin
maven("https://packages.jetbrains.team/maven/p/firework/dev") {
    content { includeGroupAndSubgroups("org.jetbrains.compose.hot-reload") }
}
```

No `includeBuild` or `mavenLocal` is needed for this published version. ART dependency remains
`io.github.ytlog:artdcevm:0.1.0-alpha.4`. README files are intentionally unchanged in this release;
use the version above when following their integration examples.

本公开版本不需要 `includeBuild` 或 `mavenLocal`。README 按要求保持不变，
使用其中的接入示例时，将插件版本替换为上面的 alpha.3。
